## 5. Customer-run checklist

1. Fill in the customer values in `terraform.tfvars`: `project_id`, `project_number`, `region`, `psc_i_network_attachment_id`, `dns_peering_config.target_network`.
2. Replace `org-469335481292` and `755577630695` in every `principals:` entry in `data/endpoints/*.yaml` with the customer's org ID and project number.
3. Create the `.` **forwarding** zone (and private Google API zones / PSC endpoint) in the customer VPC **before** `terraform apply`. Template validation fails without a `.` zone when `domains = ["."]`.
4. Create Cloud NAT on the customer VPC (or set `vpc_egress = "PRIVATE_RANGES_ONLY"`).
5. Make sure no Agent Gateway already exists for the same project and direction (only one egress gateway is allowed per project).
6. `terraform init && terraform apply`. If a policy can't resolve the freshly created gateway on the first apply, re-run it.
7. Deploy with `deploy_agent.py`, then test with `test_agent.py`. Allow 1–2 minutes after any allow-list change before testing.
